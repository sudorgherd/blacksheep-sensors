# v0.2.0 Stage 5 — RF Context and Length Reliability

**Status:** Implemented and provisionally characterized; original physical gate remains open for Stage 9 closure
**Version:** `0.2.0-dev`
**Branch:** `v0.2.0-stage5-rf-attributes`

## Objective and authority

Stage 5 determines whether RSSI, noise floor, primary channel, configured band,
derived center frequency, `sig_len`, and `dump_len` are sufficiently understood
to advance to the later milestone decision. It does not define an observation
schema or implement timing/activity characterization.

The direct metadata contract was rechecked in ESP-IDF 5.5.4
`esp_wifi_he_types.h`; band-mode and channel configuration/query contracts were
rechecked in `esp_wifi.h` and `esp_wifi_types_generic.h`. `rssi`, `noise_floor`,
`channel`, `second`, `sig_len`, and `dump_len` are direct receive metadata.
Band is configured and verified radio context. Center frequency is a
BLACKSHEEP derivation from a supported band/channel pair.

The public `dump_len` comment says MPDU length excluding FCS. Controlled Stage
1 evidence instead found `dump_len == sig_len + 4`, while `sig_len` included the
generated FCS for the tested frames. This contradiction remains explicit.

## Pre-registered decision criteria

These criteria were fixed before Stage 5 physical measurements:

| Candidate | Availability and consistency criterion | Provisional disposition rule |
| --- | --- | --- |
| RSSI | Samples in every repeated condition; finite signed values; repeated windows must show broadly coherent condition distributions without requiring strict ordering | Accept with conditions if available and useful as relative context; Experimental if spreads/condition overlap prevent coherent comparison; never ranging |
| Noise floor | Samples whenever eligible frames exist; bounded repeated-window summaries; cadence/traffic response must be understandable | Accept with conditions only if populated and coherent; otherwise Experimental or Defer |
| Primary channel | Configured channel verified through ESP-IDF; every eligible frame must match in fixed-channel windows | Accept with conditions for zero mismatches; Experimental if any unexplained contradiction occurs |
| Band | Requested band-only mode must equal queried band mode and the supported channel context | Accept with conditions only as configured/verified context |
| Center frequency | Pure mapper must exactly map every supported pair and reject every unsupported/ambiguous pair; physical channel contradictions must be zero | Accept with conditions as a derived value only |
| `sig_len` | Nonzero, repeatable for each deterministic supplied length, and consistent with independently expected FCS-inclusive length | Accept with conditions if repeated controlled evidence agrees; otherwise Experimental/Defer |
| `dump_len` | Nonzero and repeatable relation for each deterministic size, with semantics supported by documentation or retained as unresolved | Accept only with documented semantics; consistent but undocumented behavior remains Experimental/Defer |

No threshold will be relaxed after measurements. A candidate may fail its own
criterion without failing Stage 5 if it receives an honest non-Accept
disposition and the required characterization is complete.

## Pure channel and aggregation contract

The ESP-IDF-independent mapper supports only:

- US 2.4 GHz channels 1–11: `2407 + 5 × channel` MHz.
- qualified non-DFS 5 GHz channels 36, 40, 44, and 48:
  `5000 + 5 × channel` MHz.

Band is an explicit input. Unknown band, channel 0, channel 14, 6 GHz-like
numbering, and every unqualified channel return invalid with frequency zero.
The comparison helper reports match, mismatch, unavailable, or unsupported;
it never rewrites direct metadata.

Worker-side signed aggregation keeps sample count, signed 64-bit sum, minimum,
maximum, and explicit saturation. It retains no per-frame history and no
identifier. The worker also counts the four channel-comparison outcomes and
secondary-channel values (none/above/below/other). Secondary-channel semantics
remain Experimental unless independently controlled HT40 evidence is obtained.

### Validation-only controlled AP source

Near/middle/far/orientation acceptance uses a second, controlled aggregate.
An event contributes only when its Stage 2 parse succeeds, it is a management
Beacon (subtype 8), Stage 3 independently resolves both transmitter and BSSID
roles, the transmitter equals the locally configured owned AP transmitter, and
the BSSID equals the separately configured expected BSSID. Missing roles are
unavailable; another class/subtype is rejected; either comparison failing is a
nonmatch. No fallback or raw-slot guess is allowed.

The selector is disabled unless the ignored local file
`firmware/esp32-c5/src/stage5_local_config.h` explicitly enables it. Generate
that file without printing its contents using:

```powershell
cd firmware/esp32-c5
& scripts/stage5_local_config.ps1 -Transmitter '<OWNED-AP-RADIO-MAC>' -Bssid '<OWNED-AP-BSSID>'
```

The arguments use six colon-separated hexadecimal octets. The helper validates
them, writes only the ignored local header, and suppresses address values in its
status output. The same command is run with the owned 2.4 GHz AP-radio values
before building/uploading `c5_v020_stage5_24ghz`, and with the owned 5 GHz
AP-radio values before building/uploading `c5_v020_stage5_5ghz`. If the file is
absent, controlled selection fails closed as disabled. Neither configured nor
observed addresses are printed by firmware.

The general all-frame RF aggregate remains diagnostic. Controlled matrix
evidence uses only `Stage 5 controlled RSSI`, `Stage 5 controlled noise floor`,
and `Stage 5 controlled channel` summaries. Supporting counters report only
eligible, matched, nonmatched, role-unavailable, wrong-subtype, and invalid
totals.

## Capture and performance boundary

Stage 5 adds no callback statistics or conversion work. The callback still
copies normalized metadata plus at most 40 raw header bytes, uses a zero-wait
enqueue into the fixed 128-entry internal-RAM queue, retains no callback
pointer, allocates nothing dynamically, and prints nothing. RSSI, noise, band,
channel, frequency, and secondary-channel characterization occurs in the
worker or after capture stops.

The safe length-copy rule is unchanged:

```text
require sig_len != 0 and dump_len != 0
copy_length = min(sig_len, dump_len, 40)
```

No `+4` or `-4` correction is applied.

## Pre-registered physical method

Each board uses its assigned fixed band and channel, an owned controlled
transmitter, finite eight-second windows, and three repeats per principal RSSI
condition:

- near: 0.5 m, unobstructed line of sight;
- middle: 3 m, unobstructed line of sight;
- far: 8 m unobstructed, or the maximum available indoor unobstructed distance
  if 8 m cannot be achieved (the actual distance must be recorded);
- orientation: at 3 m, repeat with sensor antenna at 0°, approximately 90°,
  and approximately 180° relative to the reference orientation.

The same owned traffic method and nominal transmitter placement/settings are
held constant within each board's matrix. This is a bounded qualitative test,
not antenna-pattern measurement. RSSI may provide relative received-signal
context; it does not provide distance, location, transmitter power, identity,
or calibrated field strength.

The C5 #1 Stage 5-only 2.4 GHz validation environment uses fixed channel 5
(2432 MHz) to match the selected owned AP radio. The channel is still set and
queried through the established control path, and received metadata is compared
against channel 5 without normalization. The C5 #2 Stage 5-only 5 GHz
environment similarly uses fixed channel 48 (5240 MHz). Both overrides are
absent from normal and Stage 1–4 environments.

Noise-floor characterization uses at least three separately labelled windows:
light ordinary traffic, representative controlled traffic, and higher ordinary
owned-network traffic. A window with no frames has no noise-floor samples and
is reported as unavailable, not as a silent-channel measurement. No jamming or
interference is used.

Known-length testing uses deterministic valid owned frames at several supplied
lengths (target set: small valid, 128, approximately 512, and approximately
1000 bytes). For each size, the supplied length, independently expected
FCS-inclusive length, observed `sig_len`, observed `dump_len`, callback class,
band/channel, repetitions, and consistency are recorded. No payload is retained.

## Controlled dual-band residential evidence

One fixed owned mesh AP node supplied the controlled Beacon source throughout.
Only Beacons that passed the validation-only transmitter and BSSID checks
contributed to these summaries. Windows lasted eight seconds, normally produced
approximately 75–79 matched Beacons, reported zero channel mismatches and zero
queue drops, and retained an approximately 6 us callback average.

The route deliberately represents residential propagation rather than a
laboratory range calibration: next to the AP in the same room; bottom of the
stairs with additional distance and structure; downstairs/across the house
through multiple residential obstructions; and outside the residence several
meters from the structure while the AP remained indoors. The exterior condition
is retained specifically as an urban-residential roadside/walk-by approximation
of a fixed indoor transmitter, not reduced to a generic “far” label.

| Band/condition | Controlled RSSI run means (dBm) | Approximate mean of run means |
| --- | --- | --- |
| 2.4 GHz, next to AP | -34, -33, -38 | -35 dBm |
| 2.4 GHz, bottom of stairs | -45, -49, -48 | -47.3 dBm |
| 2.4 GHz, downstairs/across house | -49, -54, -55 | -52.7 dBm |
| 2.4 GHz, outside/several meters from house | -69, -67, -65 | -67 dBm |
| 5 GHz, next to AP (core repeat set) | -46, -45, -46 | -45.7 dBm |
| 5 GHz, bottom of stairs | -68, -68, -69 | -68.3 dBm |
| 5 GHz, downstairs/across house | -71, -71, -71 | -71 dBm |
| 5 GHz, outside/several meters from house | -91, -87, -89, -89 | -89 dBm |

An earlier valid 5 GHz near sanity window measured -51 dBm. It remains
additional evidence and is not silently folded into the registered three-run
core set. The approximate next-to-AP to exterior changes were 32 dB at 2.4 GHz
and 43 dB at 5 GHz. These coherent within-condition results demonstrate useful
relative RF context; they do not establish absolute distance, ranging,
localization, exact path loss, transmitter power, universal indoor/outdoor
thresholds, movement, or identity.

Controlled noise-floor summaries were approximately -93 to -98 dBm at 2.4 GHz
and -97 to -98 dBm at 5 GHz. This proves that the field was populated and
measurable in this residential environment. It does not establish a universal
BLACKSHEEP baseline or resolve update cadence and traffic response. A future
deployment-local baseline may be useful, but no calibration is implemented in
Stage 5.

## Provisional checkpoint and deferred integrated qualification

The Stage 5 implementation is usable as a substrate for Stages 6–8. This is a
development-sequencing checkpoint, **not** a Stage 5 PASS under the original
pre-registered physical gate. The criteria and physical method above remain
unchanged historical requirements; no threshold or test was erased, weakened,
or reinterpreted after observing results.

Current provisional dispositions are:

| Candidate | Provisional disposition | Basis and limits |
| --- | --- | --- |
| RSSI | ACCEPT WITH CONDITIONS | Repeatable relative RF context on both bands; geometry, obstruction, orientation, band, and deployment context matter; never ranging or movement proof |
| Noise floor | EXPERIMENTAL | Populated and coherent in collected windows, but cadence and labelled traffic response remain insufficiently characterized; no global baseline |
| Primary channel | ACCEPT WITH CONDITIONS | Fixed configured/query-verified channels 5 and 48; controlled comparisons reported zero mismatches |
| Band | ACCEPT WITH CONDITIONS | Configured and query-verified sensor context only, never invented per-frame metadata |
| Center frequency | ACCEPT WITH CONDITIONS | Pure derivation from a supported validated band/channel pair; 2432 and 5240 MHz in these runs |
| `sig_len` | ACCEPT WITH CONDITIONS | Stage 1 deterministic 128- and 1000-byte evidence agreed with expected FCS-inclusive lengths; broader size/band matrix remains required |
| `dump_len` | EXPERIMENTAL | Repeatably four bytes above `sig_len` in controlled evidence, but public semantics contradict observation and remain unresolved |

The safe copy rule remains `min(sig_len, dump_len, 40)` with both values
nonzero. Neither provisional length disposition changes that rule.

The following original Stage 5 qualification is explicitly deferred—not
cancelled—to **Stage 9 integrated qualification / semi-deployment closure**:

1. fixed-position 0°/90°/180° orientation matrix;
2. labelled light, representative, and higher ordinary-traffic noise windows;
3. deterministic small, approximately 128-, 512-, and 1000-byte length matrix;
4. measured distances for the formal near/middle/far geometry;
5. any missing explicit configured-versus-queried band-mode evidence; and
6. any remaining representative stability qualification.

Stage 9 will reconcile these items with both C5 boards, representative
dual-band field operation, an outdoor or semi-deployment RF environment,
deployment-local noise evidence, orientation sensitivity, known lengths,
Stage 6 timing evidence, Stage 7 PHY/rate evidence, the Stage 8 OUI decision,
queue/drop/load behavior, and the final cross-band disposition ledger. A camp
environment may be useful if available, but the requirement is a representative
semi-deployment environment and does not depend on a specific event.

Stages 6–8 may proceed because their technical substrates do not depend on a
formal Stage 5 physical PASS. No final v0.2.0 disposition is declared here.

## Privacy and open questions

No ambient or controlled production identifiers, SSIDs, BSSIDs, payloads,
captures, serial logs, or per-source histories are retained. Open questions are
the registered orientation and traffic-labelled noise behavior, the broader
controlled `sig_len` relationship, the undocumented meaning of the extra four
`dump_len` bytes, and whether `second` provides useful validated context under
available traffic. These questions remain visible for Stage 9 closure.
