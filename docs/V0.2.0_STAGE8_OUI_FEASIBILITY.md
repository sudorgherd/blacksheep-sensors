# v0.2.0 Stage 8 — OUI feasibility and privacy decision

**Status:** PASS

## Objective, authority, and terminology

Stage 8 decides when a parsed address may be considered for IEEE registry
resolution, what a match can honestly mean, and where production lookup should
live. It depends on Stage 3's already-established address extraction, semantic
roles, and classification. It does not redo those semantics or define the
v0.3.0 observation model.

The IEEE Registration Authority is the registry terminology authority. Its
[FAQ](https://standards.ieee.org/faqs/regauth/) distinguishes MA-L (24 IEEE
assigned bits and an OUI), MA-M (28 assigned bits), and MA-S (36 assigned bits,
historically OUI-36). The IEEE [registry listing page](https://standards.ieee.org/products-programs/regauth/)
publishes these as separate datasets. Consequently, a naive fixed first-three-
byte lookup covers MA-L/OUI but is not a complete resolver for current MAC
address assignments. Stage 8 uses “assignment hint,” not “manufacturer,” for a
matched public record.

## Eligibility contract

Eligibility is a pure mapping from the Stage 3 classification:

| Stage 3 address class | Stage 8 result | Registry lookup allowed |
| --- | --- | --- |
| unavailable/invalid | `INELIGIBLE_UNAVAILABLE` | no |
| broadcast | `INELIGIBLE_BROADCAST` | no |
| multicast/group | `INELIGIBLE_GROUP` | no |
| globally administered individual | `ELIGIBLE_GLOBAL_INDIVIDUAL` | yes |
| locally administered individual | `INELIGIBLE_LOCAL_INDIVIDUAL` | no |

Only a valid globally administered individual address advances to dataset
resolution. An eligible address with no match is explicitly
`ELIGIBLE_UNKNOWN`; this is distinct from every ineligible state. Ineligible,
missing, malformed, or dataset-failure paths produce no prefix result, label,
synthetic fallback, or guessed organization.

## Lookup feasibility experiment

The lookup mechanism exists only under `test/host`. Its three synthetic records
exercise 24-, 28-, and 36-bit prefixes and deterministic longest-prefix
selection. The dataset carries an explicit API version. A null dataset or null
entry table produces `DATASET_UNAVAILABLE`; a version mismatch produces
`DATASET_INCOMPATIBLE`. Both fail closed even for an otherwise eligible address.

The result owns a fixed 24-byte label buffer, is zero-initialized on entry, and
never returns a dataset pointer. Core lookup uses no allocation. Tests cover a
known match at every supported prefix length, unknown eligible, local, group,
broadcast, unavailable, null input, null dataset, version mismatch, all 256
first-octet classification boundaries, longest-prefix selection, and a
non-terminated source label. The fixtures are feasibility data, not registry
truth or a product database.

## Privacy and dataset lifecycle

- The U/L bit only establishes local administration. It does not prove privacy
  randomization, and local individual addresses are never attributed.
- Group and broadcast addresses are destinations or standardized group facts,
  not device-vendor candidates.
- Global-individual eligibility is not identity. A match can indicate a public
  address-block assignment only; it cannot establish manufacturer, model,
  owner, operator, physical device, or authenticity. Addresses may be assigned,
  bridged, virtualized, proxied, cloned, or otherwise represented indirectly.
- v0.2.0 defines no long-term address retention and introduces no persistent
  per-address history.
- Registry source, licensing, freshness, version compatibility, update,
  rollback, and no-match behavior are independent lifecycle concerns. A stale
  or incompatible dataset must be visible and must not silently produce a hint.

Replicating a registry on every C5 would consume flash, make every sensor
firmware/update lifecycle carry independently changing registry data, and
complicate provenance and rollback. Even a compact entry representation scales
with every MA-L/MA-M/MA-S record; textual assignment metadata adds more storage.
The Stage 8 sensor code instead pays 120 static bytes for aggregate evidence and
zero database bytes. A later host/control/server can update one resolver,
preserve dataset provenance/version, implement variable-prefix matching, and
return explicit unknown/failure states without reflashing every sensor.

## Sensor vs host vs defer decision

| Option | Benefit | Cost/risk | Decision |
| --- | --- | --- | --- |
| sensor lookup | immediate local enrichment | replicated dataset, firmware-coupled updates, variable-prefix and provenance complexity | reject for production |
| host/control/server lookup | centralized current dataset and explicit provenance/failure handling | requires a future bounded handoff | **accept with conditions** |
| defer all attribution | avoids privacy and lifecycle cost | discards a potentially useful supporting assignment hint | not selected |

**Architectural decision: HOST/CONTROL LOOKUP.** C5 may derive dataset-independent
eligibility from parsed address facts. A later schema may choose to hand off the
semantic role, classification/eligibility, and the address or candidate prefix
fact needed for resolution. Stage 8 intentionally freezes neither that record,
transport encoding, retention rule, nor label representation.

| Candidate | Disposition |

## Limitations, unresolved questions, and acceptance

Public registry licensing/redistribution terms, refresh cadence, provenance
format, rollback policy, future retention, and transport remain v0.3+ design
questions. Stage 8 does not ship or download an IEEE dataset. The usefulness of
assignment hints depends on a later privacy/retention decision. Both physical
windows contained material eligible and ineligible populations, establishing
that the distinction is operationally relevant without claiming broader
prevalence.

Stage 8 acceptance is **PASS**: the exact eligibility contract, deterministic
host experiment, dataset-version failure, variable-prefix limitation, both-band
aggregate evidence, clean targeted matrix, resource bounds, privacy analysis,
and HOST/CONTROL LOOKUP decision satisfy the approved gate. Repository audit
passed with no identifiers, registry dataset, capture/log artifact, build
output, REDLINE change, VERSION change, or controlled-source configuration
staged.
