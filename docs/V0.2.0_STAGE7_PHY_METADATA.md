# v0.2.0 Stage 7 — Public ESP32-C5 PHY metadata

**Status:** PASS

## Objective and authority

Stage 7 determines which fixed, public ESP32-C5 receive PHY metadata can be
carried and normalized without private interfaces.  The authority is ESP-IDF
5.5.4 `components/esp_wifi/include/esp_wifi_he_types.h`, specifically
`wifi_rx_bb_format_t` and the `CONFIG_SOC_WIFI_MAC_VERSION_NUM == 3` form of
packed `esp_wifi_rxctrl_t`, aliased publicly to `wifi_pkt_rx_ctrl_t` by
`include/local/esp_wifi_types_native.h`.

The public C5 structure supplies `rate` (5 bits), `he_siga1` (32 bits),
`he_siga2` (16 bits), `sigb_len` (10 bits), `cur_bb_format` (4 bits),
`rx_channel_estimate_len` (10 bits), and
`rx_channel_estimate_info_vld` (1 bit).  It does **not** supply decoded MCS,
bandwidth, guard interval, coding/FEC, STBC, aggregation, or NSS.  Those fields
are therefore unavailable in the Stage 7 model; private headers are not used.

## Public format contract

| Value | Public name | Meaning |
| ---: | --- | --- |
| 0 | `RX_BB_FORMAT_11B` | 11b MPDU |
| 1 | `RX_BB_FORMAT_11G` / `RX_BB_FORMAT_11A` | 11g or 11a MPDU; same value |
| 2 | `RX_BB_FORMAT_HT` | HT MPDU |
| 3 | `RX_BB_FORMAT_VHT` | VHT MPDU |
| 4 | `RX_BB_FORMAT_HE_SU` | HE SU MPDU |
| 5 | `RX_BB_FORMAT_HE_MU` | HE MU MPDU |
| 6 | `RX_BB_FORMAT_HE_ERSU` | HE ER SU MPDU |
| 7 | `RX_BB_FORMAT_HE_TB` | HE TB MPDU |
| 11 | `RX_BB_FORMAT_VHT_MU` | VHT MU MPDU |

Values 8–10 and 12–15 are unrecognized and fail closed.  The alias at value 1
cannot distinguish 11a from 11g without contextual band knowledge; the
normalized name is `11A_G`.

## Validity matrix

| Public fact | Validity rule |
| --- | --- |
| format | Only values 0–7 and 11 |
| `rate` | Recognized format and value 0–31; transmission-rate code for 11b, L-SIG Rate field otherwise |
| SIG-A1/HT-SIG/VHT-SIG scalar | Recognized HT, VHT, HE, or VHT-MU format |
| HE-SIG-A2 scalar | HE SU/MU/ER-SU/TB only |
| SIG-B length | HE MU only under the deliberately narrow Stage 7 contract |
| channel-estimate length | Only when the public valid bit is set |
| decoded MCS/BW/GI/coding/STBC/aggregation/NSS | Unavailable publicly on this C5 structure |

Zero is preserved when valid.  Unknown formats produce no valid conditional
fields.  The normalized structure owns fixed scalars and contains no pointers.
No Mbps value is derived: the public data is insufficient for a general rate
calculation.

## Raw SIG decision

**NO-GO / DEFER.**  The public fixed SIG scalars are copied and counted only.
Their comments are format-dependent but do not provide a complete portable
decoder contract.  Public normalized format and conditional rate facts already
answer the Stage 7 feasibility question; a decoder would add complexity and
format-specific inference without independent ground truth.  No raw SIG body,
pointer, or decoder was introduced.

## Representation and resources

The pure helper `wifi_normalize_phy_metadata()` accepts public fixed scalars and
returns explicit validity plus the recognized format, conditional rate kind,
fixed SIG scalars, SIG-B length, and channel-estimate length.  Firmware copies
those fields in constant time and interprets them only in the worker.

The capture event increased from 72 to 80 bytes.  The 128-entry static queue
payload therefore increased from 9,216 to 10,240 bytes of internal RAM.  The
40-byte frame prefix and queue capacity are unchanged.  The callback performs
no decoding, logging, allocation, floating point, waiting, or pointer retention.

## Controlled equipment inventory

The owned Windows client uses an RZ616 Wi-Fi 6E 160 MHz adapter whose driver
advertises 802.11b/a/g/n/ac/ax and 2.4/5/6 GHz bands.  The owned WLAN and fixed
C5 roles can exercise naturally selected formats on qualified channel 5
(2.4 GHz) and channel 48 (5 GHz).  The available controls do not independently
force every PHY mode, so association marketing or adapter capability is not
treated as per-frame PHY evidence.

## Host evidence

The strict-warning host suite passes **1,545,165 assertions**, including exact
recognized/reserved format vectors, minimum/maximum 5-bit rate values,
format-conditioned SIG validity, malformed combinations, Stage 1–6 regression,
and 100,000 deterministic randomized inputs.  MinGW still lacks ASan/UBSan
runtimes; the established strict-warning fallback passed.

## Physical evidence

Physical results use eight-second finite windows and aggregate-only output.
No identifiers or packet bodies are printed or retained.

Results distinguish all received frames, Beacon format counts, data-frame
format counts, and validation-only matched controlled Beacons.  A network
supporting HE does not imply every frame is HE; management, control, and data
frames may legitimately use different formats.

## Semantic and privacy boundary

PHY metadata is not identity, manufacturer proof, movement evidence, or a
behavioral fingerprint.  There is no persistent per-device PHY history, OUI
lookup, payload parsing, decryption, private API, or Stage 8 work.  Controlled
addresses remain only in ignored local configuration.

## Unresolved questions and acceptance

- VHT, HE SU/MU/ER-SU/TB, and VHT-MU remain physically unobserved.
- The public API does not expose decoded MCS, bandwidth, GI, coding, STBC,
  aggregation, or NSS for this C5 receive-control structure.
- The exact useful interpretation of fixed SIG scalars beyond their documented
  format-conditioned presence remains deferred; no decoder is justified.
- The 5 GHz sustained-transfer attempt produced only a modest data-count
  increase, so it is bounded functional evidence rather than a stress result.

Stage 7 **PASS**: the public API was audited, fail-closed normalization and
golden/randomized tests pass, both-board controlled evidence is coherent for
the formats actually delivered, unobserved formats are explicit, the targeted
clean matrix and guards pass, and the callback/queue/privacy contracts remain
intact.
